## 一句话定位

试讲的反馈通常是三句话：「讲得不错」「再自信一点」「多互动」。听起来都对，但下一次上台，你依然不知道**哪一句**让学生走神、**哪个问题**抛出去会冷场、**哪一段**语速快到学生跟不上。

本项目把这件事拆成两半：

- **一半用数据量化** —— 语速、提问等待、口头禅、时间分配、iFIAS 互动编码
- **一半用 AI 演出来** —— 三个性格迥异的学生当场拆台，压力条一路顶到社死结局

### 指标来源与解释边界

同一个指标可能来自实际时间戳、用户填写、文本标记、规则估算或模型推断，解释时必须区分这些来源。

| 指标 | 可以据此说明什么 | 不能据此直接断言什么 |
| :--- | :--- | :--- |
| 平均语速 | 有效字数 ÷ 对应时长；时长可能由用户填写、媒体提供或程序估算 | 仅凭总字数与总时长，不能判断某一句或某一段实际说得更快 |
| 提问等待 | 有可靠音频时间戳时可计算；文本中的「等待 3 秒」只能表示稿件标注 | 不能仅凭普通讲稿文本，测出真实课堂中已经发生的等待秒数 |
| 停顿 | 有媒体时间信息时可统计；文本停顿标记可用于检查教学设计 | 标点、换行或省略号不能直接等同于真实停顿时长 |
| 师生语言占比 | 反映输入材料中被编码为教师、学生等类别的话语单元占比 | 单方讲稿中的占比不能直接对标真实课堂中的发言时间占比 |
| 口头禅计数 | 反映输入文本中匹配到的词语次数与密度 | 转写遗漏、语境差异及关键词误匹配可能影响结果 |
| AI 学生专注、理解与压力 | 用于模拟课堂状态变化和训练反馈 | 不是对真实学生心理、理解水平或情绪的测量 |
| 六视角评分 | 用不同模拟角色帮助检查教学设计 | 不代表真实督导、家长、学生或同行的实际评价 |

**缺少可靠时间信息时，等待、停顿和局部节奏只能标为「文本标注 / 估算 / 模型推断」，不能标为「实测」。** 如果程序尚未区分这些来源，应将其作为待完善项，而不是默认已经实现。

## iFIAS 量化口径（可复现）

编码体系采用改进型弗兰德斯互动分析系统（iFIAS），14 类 / 16 个可编码值：

| 语言归属 | 编码 |
| :--- | :--- |
| 教师语言（间接） | 1 接受情感 · 2 表扬鼓励 · 3 采纳观点 · **4.1 开放提问** · **4.2 封闭提问** |
| 教师语言（直接） | 5 讲授 · 6 指令 · 7 批评或维护权威 |
| 学生语言 | 8 被动应答 · **9.1 主动应答** · **9.2 主动提问** · 10 同伴讨论 |
| 沉寂 | 11 无助于教学的混乱 · 12 有益于教学的沉寂 |
| 技术 | 13 教师操纵技术 · 14 学生操纵技术 |

**处理链路与参数（全部可在 `app/lib/ifias.js` 复现）**

| 环节 | 参数 |
| :--- | :--- |
| 话语单元切分 | 句末标点切分 → 超长句按逗号再切 → 上限 **80** 句 |
| 逐句编码 | LLM `temperature=0.2`；失败降级关键词 + 标点规则 |
| 聚合矩阵 | 12 类（4.1/4.2 合并为「教师提问」，8/9.1 合并为「学生应答」） |
| 原始矩阵 | 16×16，不聚合，对角格标红 |
| 稳态格 | 对角格计数 **≥2**（同一行为连续出现） |
| 内容十字区 | 4.1 / 4.2 / 5 三码内部转移 ÷ 全部转移 |
| 片段窗口 | 窗口 **6** 句，步长 **3** |
| 片段特征 | 7 维：教师占比、学生占比、沉寂占比、技术占比、开放提问比、间接影响比、香农熵（归一） |
| DBSCAN | `MinPts=2`，`ε` 自适应 = k-距离中位数 × 1.25，clamp **[0.22, 1.1]** |
| PCA | 中心化 → 协方差 → **Jacobi 旋转**求特征值 → 前 2 主成分 |

**为什么 ε 要自适应**：在项目测试样例中，经典 DBSCAN 的固定 ε 在只有 3–8 个片段的短讲稿上会把所有片段判成噪声（样例中 3/3 全噪声）。改为 k-距离中位数启发式后，短稿稳定得到 1 簇 + 1 噪声，长稿可分出 3 簇。这是当前样例上的工程经验，自适应参数未必是所有短文本的通用最优解。

| 指标 | 中位数 | 均值 | 对产品的意义 |
| :--- | ---: | ---: | :--- |
| 对话时长 | 119.7 s | 148.6 s | 片段长度与真实课堂节奏量级一致 |

根据项目现有统计记录，本项目还下载并分析了 SmoothConv 教育子集的部分标注 JSON。因此，本项目对公开语料的使用不只是方法论参考，也包括对标注数据进行统计分析。

| 项目 | 使用边界 |

| **音频数据** | 上述统计流程未下载或使用音频 |
| **模型训练** | 上述使用仅限统计分析，不涉及使用该数据集进行模型训练或微调 |
| **数据分发** | 项目代码仓库不应随代码附带或再分发第三方原始标注、音频及含原始内容的缓存；实际发布前需检查仓库与发布包 |

本 README 目前未附对应数据版本的许可核验材料，因此不在此保证某一种具体用途已经获准。正式发布或商业使用前，应补充原始来源、版本、许可文本及必要的署名信息。

## Key Findings（探索性观察与工程经验）

以下内容来自项目样例、调试记录与当前实现，不代表已经完成大规模教学效果验证。

- **单方讲稿天然以教师语言为主。** 当前样例中教师语言占比较高，首先反映输入材料的构成。不能仅凭这一比例认定真实课堂缺乏互动，也不能直接与师生完整对话的时间占比比较。

- **设计了提问，不等于已经发生互动。** 讲稿中的问题数量与开放程度可用于检查提问设计；真实等待、学生是否作答及回答质量，还需要时间戳、学生话语或课堂观察支持。仅凭讲稿不能确认已经发生冷场或有效互动。

- **多轮上下文有助于生成与前文相关的追问。** 项目样例中，加入近期对话后，AI 学生能够引用教师原话继续追问。这是功能表现观察；其真实性与训练收益仍需结合人工评审、对照测试及用户反馈验证。

- **短讲稿聚类对参数较敏感。** 在项目测试样例中，自适应 ε 减少了固定 ε 下全部片段被判为噪声的情况。这是当前样例上的工程经验，不代表对所有短文本都有效。DBSCAN 噪声仅表示特征空间中的低密度片段，不自动等于教学事故或教学质量异常。

- **离线兜底提高演示流程的可用性。** 内置示例数据可以在网络失败时展示主要功能，但不能替代针对当前输入的真实计算。演示结果应明确标注，不应作为个人成绩或真实成长记录。

## Ethics Statement

- **区分本地保存与网络传输。** 讲稿和历史记录的本地保存，不代表内容不会离开设备。使用在线分析时，相关输入需要发送至应用后端；启用外部模型、云端转写或视觉服务时，完成任务所需的内容还可能发送至对应服务提供方。

- **区分本地历史与云端存档。** 登录后的云端报告存档，与在线分析请求是不同的数据处理行为。实际保存字段、保存期限、访问权限和删除方式，应以实现及正式隐私说明为准，不能仅凭「默认保存在浏览器」作出不上传或不留存的保证。

- **登录后复盘会自动进入公开榜单。** 当前实现中，登录用户每次复盘都会向公开可读的榜单表写入一条记录，包含昵称、分数、学科、年级、学校与战队。这与「报告仅本人可见」是两件不同的事，需在正式隐私说明中单独告知，并提供退出上榜的开关。

- **匿名展示不等于无法关联账号。** 树洞即使不展示昵称或账号，也不代表服务端无法关联发布者。若支持云端共享，应明确展示范围、上传内容、关联标识及删除方式；若仅本地保存，则不应宣传为跨用户共享。

- **模拟反馈不是现实测量。** AI 学生状态、压力、控场得分和六视角评价用于训练与反思，不代表真实学生心理、真实课堂效果或真实评价者意见。

- **分数是参考，不是教学能力定论。** 使用相同输入口径、算法版本与评分标准进行多次练习，才更适合观察变化。模型、提示词或输入范围变化，也可能导致分数变化。

- **演示数据不得冒充个人结果。** 固定离线示例应明确标注，不应作为用户实际表现、真实成绩、榜单成绩或成长证据。

- **不替代真实教学评价。** AI 反馈不能替代导师评课、学生反馈与真实课堂经验。系统不判断谁适合当老师，也不对教师或学生作人格判断。

上述内容是产品说明应遵守的边界，不代表当前实现已经完成隐私、安全或教学有效性审计。正式发布前，需要逐项核对网络请求、第三方服务、数据存储、访问控制和删除流程。
