# iFIAS 课堂话语标注手册（v1.0）

> 用途：让两名标注员在没有商量余地的情况下独立编码同一批句子，并让由此算出的 Cohen's κ 有意义。
> 适用范围：**教师单方话语**（试讲稿、试讲转写稿）。含真实学生发言的课堂实录另见第 7 节。
> 版本日期：2026-10-30

---

## 0. 先读这一段：κ 低不等于标注员不认真

κ 低有四个来源，只有第四个是人的问题：

1. **类别本身重叠**（"提问"和"指令"在中文里共享大量句式）；
2. **手册没写清楚边界**（本手册存在的主要目的）；
3. **语料含大量模棱两可句**（"大家看这里"——看什么？）；
4. 标注员没读手册或走神。

所以流程是：先按本手册独立标 20 句 → 算一次 κ → **只讨论分歧句，不改已标结果** → 修订手册 → 重标剩余的 180 句。
如果首轮 κ < 0.60，**停下来修手册，不要硬标完**。标完再返工的成本是首轮的三倍。

## 1. 标注对象：什么是"一个单元"

系统用 `splitUnits()` 切句，规则是：按句末标点（。！？；）与换行切分，**保留长度 ≥ 2 的片段**，过滤纯标点。

人工标注时遵守同一口径，另加三条：

| 情况 | 处理 |
| :-- | :-- |
| 括号内的舞台提示，如「（板书课题）」「（停顿 1 秒）」 | **单独成单元**，按动作性质编码（板书→6，操作设备→13，停顿→12） |
| 一句话里含两个动作，如「我们来看大屏幕，这个三角形有什么特点？」 | **按主句编码**。主句 = 承载教学目标的那一半。此处为 4.1（提问），"看大屏幕"视为铺垫 |
| 语气词开头，如「嗯，很好」 | 合并到后一句一起编码，不单独成单元 |

**不要**因为一句话很短就跳过。单字片段（"对""嗯"）在真实转写中大量存在，它们是"反馈类"的重要证据。

## 2. 单方试讲稿的特殊规则（最重要）

试讲稿里没有真实学生，但**教师会替学生说话**。这四种情况必须区分：

| 写法 | 实际是什么 | 编码 |
| :-- | :-- | :-- |
| 「生：5」/「学生答：5」 | 记录的（或想象的）学生发言 | 学生类（8 / 9.1 / 9.2） |
| 「好，请坐。我们来看……」 | 教师对学生发言的回应 | 按回应性质编（2 表扬 / 3 采纳） |
| 「为什么呢？因为两条直角边平方和等于斜边平方」 | **教师自问自答（设问）** | **5（讲授）**，不是 4.1 |
| 「大家一起说，等于几？」 | 教师引导全班齐答 | 4.2（提问），不是 10（讨论） |

**第 3 条是本项目最容易错的一处。** 设问在中文课堂里极常见，形式上带问号，功能上是讲授。判据：**如果教师在同一段落里自己给出了答案，就是设问 → 5**。

## 3. 七类教师语言（八个码）：判据与典型句式

> iFIAS 的教师语言是 7 个类目（1 接受情感 / 2 表扬鼓励 / 3 采纳观点 / 4 提问 / 5 讲授 / 6 指令 / 7 批评权威），
> 其中第 4 类拆成 **4.1 开放** 与 **4.2 封闭** 两个码，所以是「7 类 8 码」。下文按码逐条给出判据。

> 只列教师类。学生类（8/9.1/9.2/10）、沉寂类（11/12）、技术类（13/14）见第 6 节。

### 1 教师接受情感
**判据**：教师明确承认并接纳学生的情绪状态，不评价对错。
典型：「别急，慢慢来」「我知道这道题让大家有点受挫」「没关系，说错也是收获」
反例：「别急，再想想」——重心在催进度，判 **6**。

### 2 教师表扬或鼓励
**判据**：对学生的**行为或结果**给出正面评价，或给出继续努力的支持。
典型：「很好」「这个思路很清晰」「你比上次进步了」「再试一次，你可以的」
反例：「对」——单字确认，判 **3（采纳）** 更准；「请坐」——是课堂常规，判 **6**。
⚠️ **已知分歧点**：`ruleCodeOne` 把「请坐」判 2。教学上它是指令。标注时按教学判据标 **6**，并在备注里写明，此处分歧要计入规则引擎的已知误差。

### 3 教师采纳学生观点
**判据**：把学生的说法**接进课堂内容**，并明确其来源是学生。
典型：「正如刚才这位同学说的」「按他的思路我们往下推」「你补充的这一点很关键」
反例：教师重复一遍正确答案但没提谁说的 → **2** 或 **5**。

### 4.1 提问开放性问题
**判据**：答案不唯一，或需要解释、推理、举例。
典型：「为什么」「你怎么想的」「还能怎么解」「这两个有什么不同」「举例说说」
**必须能通过这一问**：换一个学生回答，答案会不会明显不同？会 → 4.1。

### 4.2 提问封闭性问题
**判据**：答案唯一或只需判断/回忆。
典型：「是不是」「等于几」「谁还记得公式」「对不对」「听明白了吗」
⚠️ **确认性提问**（"听明白了吗""对不对""会了吗"）判 **4.2**，但它几乎不产生认知负荷。若一份稿子里这类占提问的多数，报告中应单独提示，而不是混在"提问率"里。

### 5 教师讲授
**判据**：教师陈述知识、解释原理、演示推理过程；**包括设问后的自答**。
典型：「因为……所以……」「第一步……第二步……」「这个概念的意思是」
反例：「我们一起来看黑板上的推导」——这是引导学生注意，判 **6**。

### 6 教师指令
**判据**：要求学生的**行为**（看、写、读、坐、打开、分组），不涉及知识内容的传递。
典型：「翻开第 32 页」「拿出练习本」「看黑板」「大家一起读」「四人一组」
反例：「看大屏幕上的这个三角形」——若重心在屏幕上的**内容**，判 5 或 4.x；若只是"看"这个动作，判 6。
⚠️ **已知分歧点**：`ruleCodeOne` 遇到「屏幕/PPT/投影」优先判 13（技术操作）。教学上"操作技术"指教师**实际动手操作设备**，不含"让学生看屏幕"。标注按教学判据标 6，记为规则引擎已知误差。

### 7 教师批评或维护权威
**判据**：负面评价、纪律压制、以权威身份终止学生行为。
典型：「安静」「怎么又是你」「不许说话」「再说就出去」
反例：「这里容易错，注意」——是提醒，判 **5** 或 **6**。

## 4. 六组高频边界（决策树）

标注时先过这六棵树，80% 的分歧会消失。

**① 带问号的句子，先问"有没有人真的回答"**
- 教师自己答了 → **5**
- 学生答了（稿里有"生："）→ 教师那句仍是 **4.x**
- 无人答、教师继续说 → **4.x**

**② 4.1 vs 4.2**
- 答案能一句话说死（数字、是/否、名词）→ **4.2**
- 需要"因为""比如""还可以"→ **4.1**
- 拿不准 → 记 **4.2** 并在备注写 "?"，一致性分析时单独看这批

**③ 4.2 vs 6**
- 「谁来回答」→ **4.2**（在要答案）
- 「你来说」→ **4.2**（点名是要答案的动作）
- 「大家一起读一遍」→ **6**（要行为，不要答案）

**④ 5 vs 6**
- 句子里有知识内容（概念、原理、步骤的依据）→ **5**
- 只有动作要求 → **6**
- 「我们来看……」后面紧跟内容 → **5**；「我们来看黑板」到此为止 → **6**

**⑤ 2 vs 3**
- 只夸做得好 → **2**
- 夸 + 把他的说法变成课堂内容 → **3**

**⑥ 12 vs 11**
- 教师安排学生思考/练习/阅读，秩序正常 → **12（有益沉寂）**
- 秩序失控、与教学无关的噪音 → **11**
- 单方试讲稿里 11 几乎不出现；若出现，多半是标注员把"教师停顿"误解成混乱

## 5. 两个口径：7 类 与 5 类

本项目报**两个 κ**，因为比较对象不同：

| 口径 | 类别 | 用途 |
| :-- | :-- | :-- |
| **8 码**（本项目主口径） | 1 / 2 / 3 / 4.1 / 4.2 / 5 / 6 / 7 | 系统实际使用的粒度 |
| **5 类**（对标口径） | 反馈(1+2+3) / 提问(4.1+4.2) / 讲授(5) / 指令(6) / 批评(7) | 与冯秀梅等(2025) 的 κ=0.871 可比 |

**报告时必须两个都报。** 只报 5 类会显得比实际好（合并降难度）；只报 7 类则无法与已有基准对话。
预期：5 类 κ 明显高于 7 类。若两者接近，说明分歧主要发生在类别之间的大边界（如 5 vs 6），而不是细分边界（如 4.1 vs 4.2），这本身就是有价值的发现。

## 6. 学生类 / 沉寂类 / 技术类（仅当语料含学生发言时）

| 码 | 判据 | 单方稿中的期望 |
| :-- | :-- | :-- |
| 8 学生被动应答 | 学生回答教师指定问题，答案可预期 | 仅"生："行 |
| 9.1 学生主动应答 | 学生自发补充、扩展 | 罕见 |
| 9.2 学生主动提问 | 学生提出问题 | 罕见 |
| 10 同伴讨论 | 学生之间交流 | 仅"小组讨论"段落 |
| 11 无助于教学的混乱 | 秩序失控 | 几乎为 0 |
| 12 有益于教学的沉寂 | 思考、练习、阅读 | 仅"（停顿）"类提示 |
| 13 教师操纵技术 | 教师**动手**操作设备 | 仅"（操作 PPT）"类 |
| 14 学生操纵技术 | 学生动手操作 | 几乎为 0 |

**单方试讲稿的必然结果**：学生类与沉寂类接近 0。报告里必须写这句话，否则读者会误以为"这个老师从不让学生说话"。

## 7. 双人标注流程

```
① 抽样：node scripts/build-annotation-set.js --input <语料目录> --n 200
   → 生成 annotation/set-200.csv（含空列 A/B）与 annotation/label.html

② 首轮：两人各标前 20 句，互不看对方结果
   → node scripts/cohen-kappa.js --a <A.csv> --b <B.csv> --limit 20
   → κ < 0.60：停下来，逐条过分歧，修订本手册第 3–4 节，重标前 20 句

③ 全量：两人各标完剩余 180 句（互不交流）
   → node scripts/cohen-kappa.js --a <A.csv> --b <B.csv>
   → 输出总 κ、7 类 κ、5 类 κ、混淆矩阵、分歧清单

④ 仲裁：对分歧句由第三人（或两人协商）定终值，写进 final 列
   → 终值列用于生成"金标准"，作为规则引擎/LLM 编码的评测基准
```

**独立性的硬要求**：标注期间不许讨论具体句子，只能讨论手册条文。讨论过的句子作废重标。

## 8. 验收线

| 指标 | 线 | 依据 |
| :-- | :-- | :-- |
| 5 类 Cohen's κ | ≥ 0.70 | 与冯秀梅等(2025) κ=0.871 同口径，0.70 是可发表的下限 |
| 8 码 Cohen's κ | ≥ 0.60 | 类别更细，按 Landis & Koch 属 "substantial" |
| 单类 κ | 不低于 0.40，且该类样本 ≥ 5 | 低于此说明该类定义失效；样本 <5 时 κ 不可解释，不要引用 |
| 未标注率 | 0 | 允许标"存疑"，但要给最可能的码，不允许留空 |
| 有效配对数 | ≥ 200 | n=30 时 κ 的 95% 置信区间宽达 ±0.2，只能做试标校准 |

**低于线怎么办**（按顺序，不要跳步）：
1. 看混淆矩阵里最大的那一格，那是主要分歧；
2. 只针对那一格改判据，重标**受影响的句子**（不是全部）；
3. 若改判据后 κ 仍 < 0.5，该类合并进上位类，并在论文里如实写"该类在本语料上不可靠"。

### 9.2 D1 的隐藏陷阱：确认语必须在句首

修 D1 时最容易写成「句子里有『好／对／是』+ 数字就算采纳」，结果把下面这些全部判错：

| 句子 | 错判 | 正确 | 原因 |
| :-- | :-- | :-- | :-- |
| 你为什么觉得是 5 呢？ | 3 采纳 | 4.1 提问 | 「是 5」是提问内容 |
| 大家先自己算一算，直角边是 3 和 4 的时候，斜边是多少。 | 3 采纳 | 6 指令 | 数字是题目条件 |
| 好，我们看第 3 题 | 3 采纳 | 6 指令 | 「好」是过渡语 |

这三条是 `scripts/rule-change-audit.js` 做全量对比时抓到的真实回归，不是假设。
判据最终写成「句首确认语 + 数字」，并把这三种情形固化成回归用例。

### 9.3 一个必须提前处理的方法学问题：先冻结代码，再抽样

`build-annotation-set.js` 是**按编码分层抽样**的。这意味着：

> 判据一改 → 编码结果变 → 分层变 → 抽到的句子换一批 → 已标注的数据作废。

本次实测到了这一点：修完 D1/D6/D7 后重新抽样，30 句里有 20 多句被换掉。
更隐蔽的后果是，若脚本按 `id` 保存手册裁决，重排后会把 A 句的裁决套到 B 句上，
**报告照样生成、数字照样好看，但每一格都是错的**。`make-selftest-annotation.js`
因此改成按**文本**匹配，并对未复核句子明确报错而不是猜。

对正式试点的要求：

1. 先冻结代码（打 tag 或记录 commit），
2. 再抽样（`--seed` 一并写进报告），
3. 再组织标注。
4. 标注期间**不许改判据**。要改，就整批重抽重标——这一点必须提前告知标注员。
