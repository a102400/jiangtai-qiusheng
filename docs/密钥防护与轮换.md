# DeepSeek 密钥防护与轮换手册

> 原则：**密钥只允许存在于两个地方** —— 本地 `app/.env`（已被 .gitignore 忽略）、部署平台的环境变量面板。
> 除这两处之外，任何文件、任何响应、任何日志里出现密钥，都按「已泄露」处置。

---

## 一、已封堵的 6 条泄露通道

### 通道 1：Docker 镜像（最隐蔽，且最难挽回）

**问题**：`Dockerfile` 里是 `COPY app/ ./`，会把 `app/.env` 一起复制进镜像层。镜像一旦被 push，即使事后删文件，密钥仍永久留存在 layer 历史里，只能轮换。

**已修**：
- 新增 `app/.dockerignore`，在 COPY 阶段就排除 `.env` / `.env.*` / 备份 / 日志
- `Dockerfile` 增加第二层保险：构建时 `rm -f .env`，若清理后仍存在则**直接构建失败**

**验证**（装了 Docker 的机器上）：
```bash
docker build -t jtq-test . && docker run --rm jtq-test sh -c "test -f .env && echo LEAK || echo SAFE"
# 预期输出 SAFE
```

### 通道 2：静态目录被浏览器直接下载

**问题**：`public/` 下的文件原样下发给任何人。一旦有人把 `.env` 或含密钥的调试脚本放进去，等于对全网公开。

**已修**（`server.js`）：
- 启动自检 `auditPublicForSecrets()`：扫描 `public/` 全部文本文件，命中 `sk-` 形态即**拒绝启动**（`process.exit(1)`）
- 静态服务拦截：`.env` / 隐藏文件 / `.bak` / `.log` / `.pem` / `.key` / `.zip` 一律 404

**验证**：
```bash
# 放一个假密钥进 public/，服务应起不来
N='sk-'; N="$N$(printf 'A%.0s' $(seq 1 24))"
echo "const k=\"$N\";" > app/public/__t.js
cd app && node server.js    # 预期：打印 [SECURITY] 并以退出码 1 结束
rm app/public/__t.js
```

### 通道 3：错误响应 / 日志回显

**问题**：原代码 6 处 `sendJson(500, { error: e.message })`；而 `deepseek.js` 抛出的 message 是 `AI_HTTP_4xx: <上游 body 前 200 字>`。部分网关会把 `Authorization` 头回显在错误里 —— 那就成了二次泄露。

**已修**：
- `deepseek.js`：message 改为纯 `AI_HTTP_<status>`，上游原文只留在 `error.upstreamBody` 且经 `scrubSecrets()` 脱敏
- `server.js`：新增 `redact()` 正则脱敏 + `serverError()` 统一出口，对外只返回「服务暂时不可用」+ traceId，堆栈只进服务端日志
- `engine.js` 的 `console.warn` 也因此不再打印上游原文

**验证**：
```bash
curl -s -X POST "http://127.0.0.1:3000/api/analyze?sharecode=xxx" -d 'not-json'
# 预期：{"ok":false,"error":"JSON 解析失败"} —— 不含任何内部细节
```

### 通道 4：健康接口泄露上游地址

**问题**：`/api/health` 原来返回 `baseUrl`，等于把供应商和接口地址直接告诉攻击者。

**已修**：只返回 `aiMode` / `model` / `hasKey`，不再下发 `baseUrl`。

### 通道 5：备份目录里的明文副本

**问题**：`备份/2026-10-23-eab/app/.env` 里存着同一把密钥的明文副本。备份包 4.6MB，很容易被整体打包发人/传网盘。

**已修**：该文件的 `AI_API_KEY` 已替换为 `sk-PLACEHOLDER_ROTATED`（文件保留，结构不变）。
**规则**：今后备份只备份代码，**不备份 `.env`**。

### 通道 6：手滑提交（最后一道人因防线）

**已修**：
- `.gitignore` 增加 `**/.env`、`*.pem`、`*.key`、`*.p12`
- 新增 `app/scripts/check-secrets.sh`：扫描**要提交的内容本身**（而非文件名），命中 `sk-` / JWT / 高权限标识即退出 1
- 新增 `.git/hooks/pre-commit` 自动调用上述脚本
- 关键设计：**git 不可用时也退出 1**（宁可拦住，不要假通过）；报告只给文件+行号，绝不打印密钥值

**验证**：
```bash
printf 'const k="sk-%s";\n' "$(printf 'A%.0s' $(seq 1 24))" > README-leak-test.md
git add README-leak-test.md
git commit -m "test"        # 预期：被拦截，退出码 1
git reset README-leak-test.md && rm README-leak-test.md
```

## 二、轮换密钥（标准流程）

> 触发条件：密钥曾出现在 git 历史 / 公开仓库 / 聊天记录 / 截图 / 日志 / 任何非 .env 的位置。
> **只删文件不够** —— 只要密钥曾经可见过，就必须轮换。

1. **生成新 key**
   登录 DeepSeek 开放平台 → API keys → 新建 → 复制（只显示一次）

2. **本地替换**
   编辑 `app/.env`：
   ```
   AI_API_KEY=sk-新的key
   ```

3. **线上替换**
   CloudStudio / Render 等平台的环境变量面板里改 `AI_API_KEY`，**不要**改仓库里的 `.env`

4. **核对指纹**
   重启服务，看启动日志：
   ```
   密钥指纹：  170f58a7
   ```
   指纹是 SHA256 前 8 位，只用于核对「线上跑的是哪把 key」，无法反推。换 key 后指纹必变。

5. **吊销旧 key**
   确认新 key 工作正常后，回平台删除旧 key。顺序不能反 —— 先删旧会导致线上立刻挂掉。

6. **确认无残留**
   ```bash
   cd E:/ai网页
   grep -rlE "sk-[A-Za-z0-9]{20,}" . --include="*.js" --include="*.html" --include="*.md" --include="*.json" 2>/dev/null | grep -v "\.git/"
   # 预期：除 jiangtai-qiusheng/app/.env 外，无任何输出
   ```

## 五、暂不轮换密钥时的补偿措施（2026-10-30 增补）

> 前提：决定不轮换密钥，该 key 继续有效。
> 此时目标从「消除风险」调整为「把最坏情况的损失限制在可接受范围内」——
> 承认密钥可能被他人使用，并保证即使发生，损失也是有上限、可发现的。

### 1. 每日调用硬上限（代码强制）

实现在 `app/lib/quota.js`，只对**真正会请求大模型**的 19 个接口计数；导出、iFIAS 矩阵等纯计算接口不占额度。

| 项目 | 值 |
|---|---|
| 当前上限 | 500 次/天（`.env` 中 `DAILY_LLM_QUOTA=500`） |
| 漏配环境变量时 | 回落到 **300**（安全默认，不是无限） |
| 显式关闭 | `DAILY_LLM_QUOTA=0`（只在明确知道风险时用） |
| 超限行为 | 返回 429「今日 AI 体验额度已用完」，**不产生任何费用** |
| 计数存储 | `app/.quota.json`，按自然日滚动，已 gitignore |
| 成本估算 | 单次分析约 ¥0.01 → 日损失上限约 ¥5 |

**为什么不用「超限就降级到规则引擎」**：`fallback_reason` 是冻结契约，只有 6 个合法取值，配额超限塞进去就是伪造降级原因。所以放在 server 层直接 429，语义干净。

**验证**：
```bash
cd app
rm -f .quota.json
DAILY_LLM_QUOTA=1 SHARECODE=t PORT=3999 node server.js &
curl -s -X POST "http://127.0.0.1:3999/api/analyze?sharecode=t" -d '{}' -w "[%{http_code}]\n"   # 400 业务错误（计 1 次）
curl -s -X POST "http://127.0.0.1:3999/api/analyze?sharecode=t" -d '{"transcript":"足够长的讲稿"}' -w "[%{http_code}]\n"  # 429
```

### 2. 余额自查（10 秒发现异常消费）

```bash
cd app && node scripts/check-balance.js
```
输出今日调用次数 + 上游账户余额。实测当前余额 **9.27 CNY**，状态正常。

### 3. 账户余额保持小额（最后一道、也是最硬的一道闸）

不要一次性充值几百元。维持 10–50 元量级，用完再充。
这是唯一**不依赖任何代码、也无法被绕过**的风险上限：即使密钥被滥用，损失天花板就是账户余额。

### 4. 异常信号清单（命中任一条立刻轮换）

- `check-balance.js` 显示今日调用数在你没使用时持续增长
- 余额下降速度明显快于你的使用量
- DeepSeek 后台用量页出现陌生时段 / 陌生模型调用
- `/api/health` 的 `quota.used` 在演示前就已很高


### 6. 关于错误分层的配套调整

统一 5xx 出口后，原本「讲稿太短」这类提示会被匿名化成「服务暂时不可用」，用户无从下手。
已引入 `bizError()`（`expose=true` 标记）区分两类错误：

| 类型 | 判据 | 响应 |
|---|---|---|
| 业务校验错误 | `expose === true` | 400 + 原始文案（讲稿太短 / 请先选原句 / 事件不存在…） |
| 其它一切异常 | 默认 | 500 + 「服务暂时不可用」+ traceId，细节只进日志 |

关键点：**默认不暴露**。新增的错误不会因为忘记处理而泄露堆栈。
