# 讲台求生 · ABD 需求梳理（2026-10-21）

> 本文档覆盖本轮迭代的三项需求：**A 战队维度**、**B 树洞云端共享**、**D 路演动线**。
> 每项包含：用户场景 → 功能定义 → 验收标准 → 技术方案 → 风险与降级。

---

## 0. 项目定位（不变）

| 项 | 内容 |
|---|---|
| 一句话 | 师范生的 AI 试讲教练：讲一次，AI 当场告诉你哪里会翻车 |
| 目标用户 | 正在准备微格教学 / 教资面试 / 师范技能大赛的师范生（首要：华南师大师范生） |
| 核心痛点 | ① 没人给逐句反馈 ② 真实课堂压力无法预演 ③ 练习没有正反馈与陪伴 |
| 现有能力 | 复盘报告（语速/等待/口头禅/危险瞬间/热力图/时间分配/课标对照/教案对照）、AI 学生拆台（单人+三学生+压力条+社死结局+挑战模式）、成长档案（历史曲线/等级/徽章/榜单/海报）、匿名树洞 |

**本轮要解决的三个空缺**

1. 榜单只有个人维度 —— 师范技能大赛是**团队集训**场景，看个人分数解决不了"我们班/我们队练得怎么样"。
2. 树洞只存在本地 —— 情感价值无法在同学之间流动，"有人和我一样翻车"这件事看不到。
3. 路演靠临场发挥 —— 3 分钟内要展示 8 个能力点，缺少一条**可排练、可计时、可降级**的固定动线。

## A. 战队维度（排行榜）

### 场景
> 教科学院 25 级 1 班这周要做师范技能大赛集训。班长想让全班都用起来，但看榜单只有"谁分高"，看不到"我们班整体什么水平、和 2 班差多少"。

### 功能定义
- 用户设置区新增 **战队/班级** 输入（如「教科院25级1班」），与昵称、学校、头像一并保存。
- 榜单新增第 4 个 Tab **「战队榜」**：按战队聚合，展示 `平均分 / 人次 / 最高分`，按平均分降序。
- 上榜数据带上 `team` 字段，匿名展示（不显示真实姓名，显示昵称）。

### 验收标准
| # | 验收点 | 判定 |
|---|---|---|
| A1 | 输入战队名并保存后，下一次复盘写入的记录带 team | DB 记录 team 非空 |
| A2 | 战队榜按平均分降序，展示 均分/人次/最高分 | 截图可用 |
| A3 | 未设置战队的记录不进入战队榜（不产生"未分组"垃圾行） | 榜中无空战队行 |
| A4 | 云服务不可用时，榜单区给出可读提示而非报错堆栈 | 断网可复现 |

### 技术方案
- DB：`leaderboard` 增加 `team TEXT`（已用 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`）。
- 数据层：`cloud.js` 增 `getTeam/setTeam`（localStorage `jtq_team`）、`pushLeaderboard` 写 `team`、`fetchLeaderboard('team')` 拉近 300 条后前端聚合。
- 视图层：`renderLbTeam(rows)` 输出战队行（战队名 + 均分徽章 + 人次 + 最高分）。
- 聚合口径：`avg = round(sum(score)/count)`，只统计 `score != null && team` 的记录。

### 风险与降级
- 风险：战队名自由输入导致同班多写法（"25级1班"/"教科院25级1班"）分裂成多行。
- 降级：本轮接受自由输入，UI 用 placeholder 引导统一格式；后续可换成"战队码"机制。

## B. 树洞云端共享

### 场景
> 一个师范生深夜试讲翻车，写完树洞只看到自己的帖子，会觉得"只有我这么差"。她需要看到**别人也翻车过**。

### 功能定义
- 新增云端表 `hollow_posts`：匿名帖正文、AI 回信、点赞数、学校、创建时间。
- 树洞卡片改为**云端优先**：拉取最近 30 条公开帖；提交时先写云端，失败则落本地（Plan B）。
- 匿名性：不显示昵称、不显示账号，只显示"匿名 · 时间 · 学校（可选）"。
- 点赞：本地累加（不回写云端，避免公开表被恶意改写）。

### 验收标准
| # | 验收点 | 判定 |
|---|---|---|
| B1 | 未登录也能发帖并立即出现在列表 | 换设备/隐私窗口可见 |
| B2 | 列表能读到其他人的帖子（≥1 条来自其他会话） | 两条不同来源 |
| B3 | 断网时仍可发帖（本地兜底），恢复后不清空本地 | 断网 → 发帖 → 有内容 |
| B4 | 帖子里没有任何可识别身份的信息 | 代码审查 + 抓包 |

### 技术方案
- DB：`hollow_posts(id, owner_id TEXT DEFAULT auth.uid(), text, reply, likes INT DEFAULT 0, school, created_at)`。
- RLS 双门：
  - `GRANT SELECT, INSERT, DELETE TO authenticated, anon`
  - `SELECT USING (true)`（公开读）、`INSERT WITH CHECK (true)`（匿名可写）、`DELETE USING (owner_id = auth.uid())`（仅本人删）
- 数据层：`fetchHollowPosts()` / `pushHollowPost({text, reply, school})`。
- 视图层：`renderHollow()` 合并云端 + 本地，云端帖带 ☁️ 标记。

### 风险与降级
- 风险 1：匿名表可能被灌垃圾内容。缓解：单条 ≤ 300 字；列表只显示最近 30 条；删除权限仅本人。
- 风险 2：`owner_id` 为 null 时 NOT NULL 约束会拦截匿名写入。规避：该列允许为空（不设 NOT NULL）。
- 降级：云服务不可用 → 完全退回 localStorage，功能不缺失、只失去跨设备。

## D. 路演 3 分钟动线

### 场景
> 黑客松决赛 3 分钟。评委不认识产品，需要一条固定顺序：痛点 → 演示 → 情绪 → 商业价值，且现场网络可能不稳。

### 功能定义
- 新增 **「🎬 路演模式」** 浮层：3:00 倒计时 + 6 个分镜，每个分镜含 `目标时间 / 讲什么 / 一键执行`。
- 分镜顺序（现场照做即可）：
  1. `0:00` 开场痛点（不操作）
  2. `0:20` 粘贴讲稿点分析 → 报告分数 + 危险瞬间
  3. `0:50` 提问等待热力图 + 时间分配（专业感）
  4. `1:20` AI 学生拆台（三学生 + 压力条）
  5. `1:50` 课堂崩塌 → 社死结局 或 挑战模式
  6. `2:20` 树洞 + 战队榜 + 海报收尾（情感与传播）
- 每步可单独重跑；倒计时到点变红提示"该往前走了"。
- 断网提示：所有执行按钮走双引擎降级，断网仍能跑（离线演示数据）。

### 验收标准
| # | 验收点 | 判定 |
|---|---|---|
| D1 | 打开浮层即开始 3:00 倒计时，可暂停/重置 | 视觉可验 |
| D2 | 6 个分镜各自的"执行"能触发对应功能 | 逐步点击 |
| D3 | 倒计时剩余 0:30 时视觉转为警示色 | 视觉可验 |
| D4 | 断网状态下点执行不报错（走离线数据） | 断网可复现 |

### 技术方案
- 纯前端：`#roadshowOverlay` 浮层 + `ROADSHOW_STEPS` 数组 + `setInterval` 计时（`requestAnimationFrame` 不必要）。
- 执行器 `runRoadshowStep(i)` 用 `switch` 调用现有函数：`runAnalyze()`、`switchTab()`、`classNextRound()`、`startCrisis()`、`renderPoster()`。
- 脚本随浮层一起呈现（每步"讲什么"即逐字稿），另出 `docs/roadshow-3min.md` 供打印。

### 风险与降级
- 风险：现场网络慢导致某步加载超过 20 秒，打乱节奏。缓解：每步按钮旁标注"预计 3–6 秒"；超时可跳过，`离线演示` 徽章会亮。
- 风险：演讲者忘词。缓解：浮层内直接显示该步逐字稿，可照读。
