## 2. 技术架构与硬约定

### 2.1 当前形态

- `app/` 是**零依赖 Node 后端**（只用内置 `http` / `fs` / `path` / `fetch`），无 Express、无构建步骤
- 前端是纯静态页，放在 `app/public/`
- 启动：`node server.js`，默认端口 3000
- 另有离线单文件版 `讲台求生-离线版.html`（当前约 439.4 KB），由 `app/scripts/build-standalone.js` 生成

### 2.2 双引擎铁律（最重要的一条）

- 有 DeepSeek Key → 走 LLM
- 无 Key 或调用失败 → **自动降级本地规则引擎**
- 前端 `post()` 网络失败 → 进入「离线演示模式」（`demo-data.js`）
- **所有新接口必须同时补：① 规则兜底 ② DEMO 数据**。这是路演 Plan B，不许只做 LLM 路径

### 2.3 密钥安全铁律

- API Key 只在服务端 `.env`
- 禁止 `NEXT_PUBLIC_` 之类任何会进前端的变量前缀
- 禁止 Key 出现在任何前端文件、离线版 HTML、DEMO 数据里

### 2.4 云服务

- applicationId：`wbapp_G19b8uinF8NS1zn0yxJPYR`
- 表：
  - `lesson_reports`：私有，本人读写
  - `leaderboard`：公开读 / 本人写，字段含 `school` / `avatar` / `team`
  - `hollow_posts`（树洞）：公开读 / 匿名可写 / 本人可删
- RLS 双门：**GRANT + POLICY 都要给**，少一个就 403
- `owner_id TEXT DEFAULT auth.uid()` 如果设成 NOT NULL 会挡住匿名写入 —— 树洞表因此允许 `owner_id` 为空

### 2.5 选型

- ASR：优先本地 `faster-whisper small`（离线、不怕断网），次选 Whisper API
- LLM：DeepSeek / 通义千问；AI 学生角色 `temperature` 用 0.85–0.95 才有人味
- iFIAS 互动分析：`app/lib/ifias.js` 零依赖自实现（14 类 / 16 码编码 + 12×12 与 16×16 双矩阵 + 稳态格 + 内容十字区 + DBSCAN 自适应 ε + 自写 Jacobi PCA），接口 `/api/ifias`（单节课）与 `/api/ifias-batch`（多节课轨迹）

## 3. 本会话的三批需求（用户原意逐条还原）

### 第一批：统一等待指标契约

用户要求：

1. 新增**统一出口 `wait_metrics`**，让 `/api/analyze` 与 `/api/heatmap` 的等待数据同源，不许两个接口各算一套
2. **没有提问时返回空数组 + `average_sec: null`**，绝对禁止伪造 0 秒，也禁止塞中性占位条目充数
3. 保留旧字段做兼容，但来源必须统一到四类：`text-heuristic` / `model-inference` / `timestamp` / `unmeasured`

### 第二批：整理教学环节语义

用户要求：

1. `knowledge` 字段**只允许七个教学环节**，模型不得覆盖、不得自由发挥
2. 学科知识点独立放 `subject_knowledge`，且**证据必须来自逐字稿原样内容**（要能 grep 回原文）
3. 修正页面标题：原本「教案逐点比对」和「七环节线索」被混成一个盒子，必须拆开

### 第三批：三件事，其中一件明确说不做

用户原话要点：

1. **拆分 `isQuestionSentence()` 与 `isInteractiveSentence()`** —— 原实现把陈述句误判成提问，导致等待指标虚高
2. 限流时降级提示显示「请求过于频繁」，但仍要说明「本报告是规则计算结果」，不能装作正常
3. **暂不启用 `source:'timestamp'`** —— 原话意思：必须等转写数据真的提供可用时间戳、并且能识别说话人之后再启用；**没有可靠时间戳与说话人信息时，绝不显示真实等待实测值**

## 4. 裁决细则（口径表，改动后的事实标准）

### 4.1 等待指标

- 唯一实现：`app/lib/wait-metrics.js`
- 导出：`buildTextWaitMetrics()`、`normalizeModelWaitMoments()`、`summarizeWaitMoments()`
- 无提问 → `moments: []` + `average_sec: null`，前端显示「无法测量」而非 0s
- 「等」的匹配不能裸匹配单字（会命中「等于」「等级」），必须是「等一等 / 稍等 / 等待 / 等一下」等上下文

### 4.2 问句判定

- 唯一实现：`isQuestionSentence(sentence)`
- 互动任务判定独立：`isInteractiveSentence(sentence)`
- 句末「吗 / 呢 / 呗」**不能单独证明是问句**，必须有疑问结构佐证
- 疑问词可以出现在**句中**（不限句首），否则会漏掉「你为什么这么想」这类
- 但要排除名词用法：「几个」「如何」作名词时要剔除

### 4.3 切句

- 切句必须**保留标点**，否则问号丢了就没法判问句
- 等待推断用 `splitSentencesKeepPunct()`
- 教学单元用 `splitTeachingUnits()`（按教学语义切，不是按句号切）

### 4.4 模型降级原因（封闭契约）

只允许这六个值，不许自由扩展：

```js
none
key-not-configured
rate-limited
insufficient-balance
auth-failed
model-error
```

- `deepseek.js` 把 HTTP 状态映射成稳定错误码，**结构化信号优先于 message 正则**（先看 status / error.code，再兜底猜文字）
- 错误对象附带 `status` / `code` / `upstreamBody` 三个字段
- 前端映射成中文提示，例如 402 → 「规则计算 · 模型账户余额不足，请联系部署方充值」

### 4.5 来源标签

- 统一函数：`describeSourceLabel()` / `sourceTagClassName()` / `degradedSuffix()`
- 已知来源：`text-heuristic`（文本启发式）、`model-inference`（模型推断）、`unmeasured`（未测量）
- `timestamp` 已从映射表删除；万一误入，显示「来源未明确」

## 6. 踩坑与修复记录（都是真实发生过的）

1. **规格里的切句会丢问号** → 换成保留标点的 `splitSentencesKeepPunct()`
2. **规格说「呢即问句」与验证清单冲突** → 裁决：必须有疑问结构佐证，句末语气词不算
3. **规格要求疑问词在句首** → 会漏掉无问号问句，改成句中匹配 + 排除高误判词
4. **单字「等」误命中「等于」** → 等待值 2.5 被抬到 3 秒，改上下文匹配
5. **前端 `Number(null) === 0`** → 缺值被画成红色「0s」，改成显式屏蔽空值，显示「无法测量」
6. **`planBox` 被错命名成七环节** → 改名「教案逐点比对」，另建「通用教学环节线索」盒子
7. **`drill.js` 里有一份同名宽松问句函数** → 问号计数和句级计数分裂，统一共享判定与统计口径
8. **密度 `0.33/min` 被显示成「0 个」** → 改成「约每 3 分钟 1 个」
9. **`server-boot-gate` 偶发 `ECONNRESET`** → 改动态端口 + 捕获子进程日志；**明确拒绝用「加重试」来掩盖真实回归**
10. **线上 API Key 返回 402** → 后端准确标记 `insufficient-balance`，前端显示「规则计算 · 模型账户余额不足，请联系部署方充值」

## 12. 这个项目的「设计哲学」（我认为最值得记住的一条）

整轮工作反复在守同一条线：**宁可显示「无法测量」，也不要显示一个好看但假的数字。**

- 没提问 → `null`，不是 `0`
- 没时间戳 → `unmeasured`，不是 `timestamp`
- 模型挂了 → 明说 `rate-limited` / `insufficient-balance`，不是悄悄给个规则结果装作模型算的
- 模型想改七环节 → 强制保留规则版

这条线是产品的可信度底线，也是这个参赛作品跟「套壳 GPT」拉开差距的地方。
