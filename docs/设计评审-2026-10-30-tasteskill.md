## Top three problems（按修复收益排序，不是按严重度）

### 1. 首屏没有标题，最上面一行是技术状态栏
**证据**：`desktop-fold.jpg` / `mobile-fold.jpg`。`mobile` 上前三行全是「未登录 / 模型服务已配置 / 模型: deepseek-chat / 介绍 / Codex / 路演 / 自动演示」——7 个胶囊芯片吃掉手机首屏 1/3；真正的产品说明被挤到第二屏。`inspect.mjs` 的 `no-title` FAIL 与之对应：`headings: 1 · longest 1 line · median 1 word`。

**为什么是问题**：陌生人 5 秒内必须能回答"这是什么、给谁用、我该点什么"。现在他看到的是"模型: deepseek-chat"——这是开发者的调试信息，不是用户的决策信息。

**修法**：
- 首屏加一个真 `h1`：「讲台求生」+ 一句功能说明（「师范生试讲教练：AI 学生拆台，课堂会崩，你在压力爆表前讲完」）。
- 顶部七个芯片收进一个「状态」抽屉，只留「未登录/已登录」+ 一个「介绍」。`模型: deepseek-chat` 属于诊断信息，移到「设置」里。

### 2. hero 是一条扁横幅，右半屏是空的
**证据**：`desktop-fold.jpg`。hero 高度约 100px，左侧三行 14px 小字，右侧两个按钮，中间 400px 纯空白。`inspect.mjs`：`page 2.3 screens · 91 words · hero media 100% canvas`——它的"hero media"是一个 canvas 光晕，没有任何信息。

**为什么是问题**：这是整页 40% 设计权重里最贵的一块地，现在只承担了"一句口号 + 两个按钮"。而项目最有说服力的东西（压力条、三学生、崩塌瞬间）全都藏在第三屏。

**修法**：hero 换成「标题 + 一句话 + 一个主按钮 + 一个真实界面片段」——把三学生课堂那一屏（压力条 87/100、小皮正在抬杠、小走已飘）直接做成 hero 里的真实片段（带 `data-ui` 属性的真组件，不是截图）。这是本项目唯一"别人抄不走"的画面，比任何渐变都值钱。

### 3. 层级全靠 1px 边框，面板套四个盒子
**证据**：`desktop-fold.jpg` 下半部分：`.panel` 里依次是「上传试讲视频」「试讲课题/学段」「教学任务与学情（可选）」「高级设置：评分标准、双人对比、教案与时长」——四个描边圆角盒，每个都是 1px 边框 + 同色填充。`inspect.mjs`：`outlined-box` 5 处、`hairline` 4 处、`shadow` 3 处。

**为什么是问题**：边框是最弱的层级手段（它只画一条线，不建立面）。深色主题里正确的做法是**色调分层**：页面底色 → 面板（+3% 亮度）→ 区块（+3%）→ 输入框（再 +2%）。现在所有东西都在同一个亮度平面上，用户要靠读边框才知道谁包含谁。

**修法**：
- 删掉所有静止元素的 `box-shadow`（深色主题下它本来就看不见，只是被测量抓到）。
- 四个描边盒改成**同一面板内的分节**（小节标题 + 间距），只有输入框保留填充。
- 装饰细线只留 topbar 一条。

## 例外清单（需要你逐条 go / no-go）

按 skill 的规定，这些都是"要么改，要么明确豁免"。我不会擅自保留。

**A. 学生头像用 emoji（😈🤓😵）—— 建议改，但要你确认**
`students-art.js` 已经有三位学生的 SVG 立绘（透明背景、矢量、`raise/default/closed` 三态）。卡片上再放一个 emoji 头像是**冗余的第二套身份系统**。建议卡片头像改成立绘的裁切缩略图。
风险：立绘在小尺寸（28px）下细节会糊，需要单独做一版"头像裁切"。

**B. 步骤条 01/02/03 —— 建议保留但改写**
三步是真实流程（准备 → 复盘演练 → 成长档案），删掉编号会丢失"我现在在第几步"。建议：保留"三选一"的结构，把 `01` 换成"第一步"这类文字，或改成进度点（● ● ○）。**是否接受"改成进度点"？**

**C. `#fxAurora` 渐变光晕 —— 建议豁免一次**
深色 + 星点 + 极淡的紫色光晕是这个产品的氛围底座，删掉会变成纯黑面板。它只出现在 hero 背景，不承载信息。
**建议**：作为唯一例外保留，但把不透明度从 `0.3` 降到 `0.16`（现在偏"AI 默认紫"）。**是否批准这一条例外？**

**D. 零真实图片 —— 建议用"真实界面片段"代替图库照片**
这是工具型 Web App，没有真实照片可用；硬塞图库素材（教室、黑板）反而是 skill 自己反对的"通用图片"。
skill 允许「软件展示自己的界面」：把三学生课堂、压力条、崩塌覆盖层做成**真组件片段**（带 `data-ui`），计为 interface fragment。
**建议**：做 3–4 个真实界面片段顶替图片位。**是否接受这条路线？**

**仍在的 5 条，逐条定性：**

1. `numbering`（01/02/03）—— 用户 2026-10-30 明确保留（no-go）。这是需要「我现在在第几步」的真实流程指示。

5. `few-pictures` 1 个 interface fragment —— 例外 D 只落了首屏这一处。要做到 ≥4 得在结果区再放三个真实组件快照，但结果区在「未提交讲稿」时是 `display:none` 的，需要它自己先跑一遍分析才可见。留待后续。
